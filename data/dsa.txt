SECTION 1: INTRODUCTION TO ALGORITHMS AND COMPLEXITY ANALYSIS
================================================================================

An algorithm is a well-defined, step-by-step computational procedure that takes 
some value (or set of values) as input and produces some value (or set of 
values) as output. An algorithm is essentially a tool for solving a specific 
computational problem.

1.1 PROPERTIES OF A CORRECT ALGORITHM
-------------------------------------
- Input: Zero or more quantities externally supplied.
- Output: At least one quantity produced.
- Definiteness: Each instruction must be clear, unambiguous, and precise.
- Finiteness: The algorithm must terminate after a finite number of steps for 
  all test cases.
- Effectiveness: Every operation must be basic enough that it can, in principle, 
  be executed exactly and in a finite amount of time using paper and pencil.

1.2 WHY STUDY DATA STRUCTURES AND ALGORITHMS?
---------------------------------------------
Data structures provide an organized way of storing and managing data so that 
operations can be performed efficiently. Algorithms represent the logic used to 
manipulate this data. Selecting the wrong data structure or algorithm can turn an 
instant operation into one that takes hours or days to execute.

1.3 TIME VS SPACE TRADEOFFS
---------------------------
Most algorithmic optimization involves trading memory usage (space) for speed (time), 
or vice versa. 
- Example: Hash tables use additional memory to achieve O(1) average lookup time.
- Example: In-place sorting algorithms (like Heap Sort) use O(1) extra space but 
  may perform more write operations than algorithms requiring auxiliary memory.

SECTION 2: ASYMPTOTIC NOTATIONS AND MATHEMATICAL FOUNDATIONS
================================================================================

Asymptotic analysis describes the behavior of algorithm performance as the input 
size 'n' approaches infinity. It allows us to compare algorithms independently of 
hardware, programming language, or execution environment.

2.1 BIG-O NOTATION (UPPER BOUND)
--------------------------------
Formal Definition:
f(n) = O(g(n)) if there exist positive constants 'c' and 'n0' such that:
0 <= f(n) <= c * g(n) for all n >= n0.

Big-O provides a formal upper bound on the growth rate of a function. It guarantees 
that an algorithm will not perform worse than the specified limit.

2.2 BIG-OMEGA NOTATION (LOWER BOUND)
-----------------------------------
Formal Definition:
f(n) = Omega(g(n)) if there exist positive constants 'c' and 'n0' such that:
0 <= c * g(g(n)) <= f(n) for all n >= n0.

Big-Omega defines the lower bound of an algorithm's execution time.

2.3 BIG-THETA NOTATION (TIGHT BOUND)
------------------------------------
Formal Definition:
f(n) = Theta(g(n)) if and only if f(n) = O(g(n)) and f(n) = Omega(g(n)).
That is, there exist positive constants c1, c2, and n0 such that:
0 <= c1 * g(n) <= f(n) <= c2 * g(n) for all n >= n0.

2.4 COMMON COMPLEXITY CLASSES (ORDERED BY GROWTH RATE)
------------------------------------------------------
1. O(1)       - Constant Time (e.g., Array element lookup, Stack push/pop)
2. O(log n)   - Logarithmic Time (e.g., Binary Search, Balanced BST operations)
3. O(n)       - Linear Time (e.g., Array traversal, Linear Search)
4. O(n log n) - Linearithmic Time (e.g., Merge Sort, Quick Sort average, Heap Sort)
5. O(n^2)     - Quadratic Time (e.g., Bubble Sort, Insertion Sort, Selection Sort)
6. O(n^3)     - Cubic Time (e.g., Standard Matrix Multiplication)
7. O(2^n)     - Exponential Time (e.g., Recursive Fibonacci, Subsets generation)
8. O(n!)      - Factorial Time (e.g., Traveling Salesperson brute force)

2.5 MASTER THEOREM FOR DIVIDE-AND-CONQUER RECURRENCES
-----------------------------------------------------
For recurrence relations of the form:
T(n) = a * T(n / b) + f(n), where a >= 1 and b > 1.

Let c_crit = log_b(a).

Case 1: If f(n) = O(n^(c_crit - epsilon)) for some epsilon > 0, 
        then T(n) = Theta(n^(log_b(a))).
Case 2: If f(n) = Theta(n^(c_crit) * log^k(n)) for k >= 0, 
        then T(n) = Theta(n^(log_b(a)) * log^(k+1)(n)).
Case 3: If f(n) = Omega(n^(c_crit + epsilon)) for some epsilon > 0, 
        and if a * f(n / b) <= c * f(n) for some c < 1 and large n,
        then T(n) = Theta(f(n)).

SECTION 3: ARRAYS, DYNAMIC ARRAYS, AND STRINGS
================================================================================

3.1 STATIC ARRAYS
-----------------
An array is a contiguous block of memory housing elements of identical types.
- Access: O(1) via base_address + index * element_size.
- Insertion/Deletion at end: O(1) [if space available].
- Insertion/Deletion at middle/beginning: O(n) due to shifting.

3.2 DYNAMIC ARRAYS
------------------
Dynamic arrays (e.g., std::vector in C++, ArrayList in Java, list in Python) 
automatically resize when full.
- Growth Strategy: When full, allocate new array of size (2 * current_capacity), 
  copy existing elements, and free old memory.
- Amortized Analysis of Push Back:
  n push operations require 1 + 2 + 4 + ... + n total copies = 2n copies.
  Amortized time per insertion = 2n / n = O(1).

3.3 STRINGS AND STRING MANIPULATION
-----------------------------------
Strings are arrays of characters ending with a null-terminator (in C) or managed 
with explicit lengths (in C++, Java, Python).
- Two-pointer technique: Reversing strings, palindrome verification.
- Sliding Window technique: Substring matching, maximum consecutive elements.

SECTION 4: LINKED LISTS
================================================================================

Linked lists consist of nodes where each node contains a data payload and one or 
more pointers (references) to adjacent nodes.

4.1 SINGLY LINKED LIST
----------------------
Node Structure:
  struct Node {
      int data;
      Node* next;
  };

Operations:
- Insertion at Head: O(1)
- Insertion at Tail: O(1) with tail pointer, O(n) without
- Deletion at Head: O(1)
- Search: O(n)

4.2 DOUBLY LINKED LIST
----------------------
Node Structure:
  struct Node {
      int data;
      Node* prev;
      Node* next;
  };

Advantages:
- Can be traversed backward and forward.
- Node deletion given pointer to node is O(1).

4.3 CIRCULAR LINKED LIST
------------------------
The last node points back to the head node. Useful for round-robin scheduling algorithms.

4.4 FLOYD'S CYCLE-FINDING ALGORITHM (TORTOISE AND HARE)
------------------------------------------------------
To detect if a linked list contains a loop:
- Maintain slow pointer (moves 1 step) and fast pointer (moves 2 steps).
- If slow == fast, a cycle exists.
- To find the start of the cycle: Move slow to head, advance both 1 step at a time; 
  they will meet at the cycle entrance.

SECTION 5: STACKS AND QUEUES
================================================================================

5.1 STACK (LIFO: LAST-IN, FIRST-OUT)
------------------------------------
Abstract Data Type supporting:
- push(x): Inserts item x onto top. O(1)
- pop(): Removes top item. O(1)
- peek()/top(): Returns top item without removal. O(1)

Applications:
- Function call stacks (Recursion management)
- Expression evaluation (Infix to Postfix conversion using Shunting-yard algorithm)
- Undo/Redo operations in text editors
- Parenthesis balance checking

5.2 QUEUE (FIFO: FIRST-IN, FIRST-OUT)
-------------------------------------
Abstract Data Type supporting:
- enqueue(x): Adds element x to back. O(1)
- dequeue(): Removes element from front. O(1)
- front(): Returns front element. O(1)

Variants:
- Circular Queue: Avoids memory waste in array implementation.
- Double-Ended Queue (Deque): Insertions and deletions at both front and back in O(1).

5.3 MONOTONIC STACKS AND QUEUES
-------------------------------
A monotonic stack maintains elements in strictly increasing or decreasing order.
Used for:
- Next Greater Element problem in O(n) time.
- Largest Rectangle in Histogram in O(n) time.
- Sliding Window Maximum using Monotonic Deque in O(n) time.


================================================================================
SECTION 6: HASH TABLES AND HASHING
================================================================================

A Hash Table map keys to values using a Hash Function to compute an index into 
an array of buckets.

6.1 HASH FUNCTIONS
------------------
A good hash function must:
- Be fast to compute O(1).
- Uniformly distribute keys across buckets.
- Minimize collisions.

Common Techniques:
- Division Method: h(k) = k mod m
- Multiplication Method: h(k) = floor(m * (k * A mod 1))
- Polynomial Rolling Hash (for Strings): h(s) = sum(s[i] * p^i) mod m

6.2 COLLISION RESOLUTION TECHNIQUES
-----------------------------------
1. Separate Chaining (Open Hashing):
   Each bucket contains a linked list or balanced search tree (e.g., Red-Black tree in Java 8+ HashMap).
   - Time Complexity: O(1 + alpha) where alpha = n/m (load factor).

2. Open Addressing (Closed Hashing):
   All elements are stored within the table itself.
   - Linear Probing: h(k, i) = (h'(k) + i) mod m. Subject to Primary Clustering.
   - Quadratic Probing: h(k, i) = (h'(k) + c1*i + c2*i^2) mod m. Subject to Secondary Clustering.
   - Double Hashing: h(k, i) = (h1(k) + i * h2(k)) mod m. Eliminates clustering.


================================================================================
SECTION 7: TREES AND BINARY SEARCH TREES
================================================================================

7.1 TREE TERMINOLOGY
--------------------
- Root: Topmost node without parents.
- Leaf: Node with no children.
- Depth: Number of edges from root to target node.
- Height: Number of edges on longest path from node to a leaf.

7.2 BINARY TREES
----------------
Each node has at most two children (left and right).
Types:
- Full Binary Tree: Every node has 0 or 2 children.
- Perfect Binary Tree: All interior nodes have 2 children, all leaves are at same level.
- Complete Binary Tree: All levels filled except possibly the last, which is filled from left to right.

7.3 TREE TRAVERSALS
-------------------
- Pre-Order (Root, Left, Right): Used for copying trees, serialization.
- In-Order (Left, Root, Right): Returns elements in sorted order for BST.
- Post-Order (Left, Right, Root): Used for deletion, evaluating expression trees.
- Level-Order (BFS): Explores nodes level by level using a Queue.

7.4 BINARY SEARCH TREE (BST)
----------------------------
Property: For any node X, all values in X's left subtree are < X.val, and all values 
in X's right subtree are > X.val.
- Search: O(h) where h is height. Average O(log n), Worst O(n).
- Insertion: O(h)
- Deletion: O(h)
  Case 1: Leaf node -> simply delete.
  Case 2: One child -> point parent to child.
  Case 3: Two children -> replace with In-Order Successor (smallest in right subtree), then delete successor.


================================================================================
SECTION 8: BALANCED SEARCH TREES
================================================================================

8.1 AVL TREES (HEIGHT-BALANCED BST)
-----------------------------------
- Property: For every node, Balance Factor = |Height(Left) - Height(Right)| <= 1.
- Guarantees O(log n) worst-case search, insertion, and deletion.
- Rebalancing Operations (Rotations):
  1. Left-Left (LL) Heavy -> Single Right Rotation
  2. Right-Right (RR) Heavy -> Single Left Rotation
  3. Left-Right (LR) Heavy -> Left Rotate Child, then Right Rotate Parent
  4. Right-Left (RL) Heavy -> Right Rotate Child, then Left Rotate Parent

8.2 RED-BLACK TREES
-------------------
Self-balancing search tree where each node is colored Red or Black.
Properties:
1. Every node is either Red or Black.
2. The root is always Black.
3. Every leaf (NIL) is Black.
4. If a node is Red, both its children must be Black (No consecutive Red nodes).
5. Simple paths from any node to descendant leaves contain equal number of Black nodes.
- Maximum Height: 2 * log2(n + 1). Less rigid balancing than AVL, leading to faster insertions/deletions.

8.3 B-TREES
-----------
Self-balancing search tree designed for systems with secondary storage (disks/SSDs).
Nodes can have hundreds of children, maximizing block reads.


================================================================================
SECTION 9: HEAPS AND PRIORITY QUEUES
================================================================================

9.1 BINARY HEAP
---------------
A complete binary tree satisfying the Heap Property:
- Max-Heap: Parent node >= Child nodes.
- Min-Heap: Parent node <= Child nodes.

Array Representation:
For element at index 'i' (0-indexed):
- Left Child: 2*i + 1
- Right Child: 2*i + 2
- Parent: floor((i - 1) / 2)

Key Operations:
- Insert (Push): Append to array, sift-up (bubble-up). Time: O(log n)
- Extract Min/Max (Pop): Swap root with last element, pop last, sift-down. Time: O(log n)
- Build Heap from Unsorted Array: Bottom-up heapify. Time: O(n) [Non-trivial math proof]

SECTION 10: GRAPH THEORY & TRAVERSALS
================================================================================

A Graph G = (V, E) consists of a set of vertices V and edges E.

10.1 GRAPH REPRESENTATIONS
--------------------------
1. Adjacency Matrix:
   V x V boolean/weight matrix.
   - Space: O(V^2)
   - Edge lookup: O(1)
   - Suitable for dense graphs.

2. Adjacency List:
   Array of lists where list[i] contains neighbors of vertex i.
   - Space: O(V + E)
   - Suitable for sparse graphs.

10.2 BREADTH-FIRST SEARCH (BFS)
-------------------------------
Traverses graph layer by layer using a Queue data structure.
- Shortest path on unweighted graphs.
- Time Complexity: O(V + E)
- Space Complexity: O(V)

10.3 DEPTH-FIRST SEARCH (DFS)
-----------------------------
Explores as deep as possible along each branch before backtracking using a Stack (or Call Stack).
- Applications: Connected components, topological sorting, cycle detection.
- Time Complexity: O(V + E)
- Space Complexity: O(V)


================================================================================
SECTION 11: SHORTEST PATH ALGORITHMS
================================================================================

11.1 DIJKSTRA'S ALGORITHM
-------------------------
Finds single-source shortest path in weighted graphs with non-negative edge weights.
- Greedy Approach using Min-Priority Queue.
- Time Complexity: O((V + E) log V) with Binary Heap.
- Algorithm:
  1. Set dist[src] = 0, dist[v] = infinity for all other v.
  2. Push (0, src) into Min-PQ.
  3. While PQ not empty:
     a. Extract u with min dist.
     b. For each neighbor v with weight w:
        if dist[u] + w < dist[v]:
           dist[v] = dist[u] + w
           Push (dist[v], v) to PQ.

11.2 BELLMAN-FORD ALGORITHM
---------------------------
Handles graphs with negative edge weights and detects negative weight cycles.
- Dynamic Programming approach.
- Relax all E edges V - 1 times.
- Time Complexity: O(V * E)
- If relaxation succeeds on the V-th iteration, a negative cycle exists.

11.3 FLOYD-WARSHALL ALGORITHM
-----------------------------
All-Pairs Shortest Path algorithm.
- Dynamic Programming approach using adjacency matrix.
- Recurrence: dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
- Time Complexity: O(V^3)
- Space Complexity: O(V^2)


================================================================================
SECTION 12: MINIMUM SPANNING TREES (MST)
================================================================================

An MST of a connected, weighted, undirected graph is a subgraph that connects all 
vertices with minimal total edge weight and no cycles.

12.1 KRUSKAL'S ALGORITHM
------------------------
1. Sort all edges in non-decreasing order of weight.
2. Initialize Disjoint Set Union (DSU) structure for vertices.
3. Iterate through sorted edges; add edge to MST if it connects two disconnected components.
- Time Complexity: O(E log E) or O(E log V).

12.2 PRIM'S ALGORITHM
---------------------
1. Start from an arbitrary vertex.
2. Use Min-PQ to track minimum weight edge connecting tree to non-tree vertices.
3. Expand tree greedily.
- Time Complexity: O(E log V) with Priority Queue.


================================================================================
SECTION 13: ADVANCED GRAPH TOPICS
================================================================================

13.1 TOPOLOGICAL SORTING
------------------------
Linear ordering of vertices in a Directed Acyclic Graph (DAG) such that for every 
directed edge u -> v, vertex u comes before v.
- Kahn's Algorithm (BFS based): Uses In-Degree array and Queue.
- DFS Method: Push node to stack after visiting all descendants; reverse stack.
- Time Complexity: O(V + E)

13.2 STRONGLY CONNECTED COMPONENTS (SCC)
----------------------------------------
Maximal subgraphs where every vertex is reachable from every other vertex.
- Kosaraju's Algorithm: 2 DFS passes (Original Graph + Transposed Graph). O(V + E)
- Tarjan's Algorithm: Single DFS pass using discovery times and low-link values. O(V + E)


================================================================================
SECTION 14: DISJOINT SET UNION (DSU)
================================================================================

Data structure tracking partitions of a set into disjoint subsets.
Operations:
- find(i): Returns root representative of element i.
- union(i, j): Merges sets containing i and j.

Optimizations:
1. Path Compression: Point all intermediate nodes directly to root during find().
2. Union by Rank/Size: Attach smaller tree under root of larger tree.

Amortized Complexity: O(alpha(N)) per operation, where alpha is the Inverse Ackermann 
function (effectively constant O(1) for all practical purposes).

SECTION 15: RECURSION AND BACKTRACKING
================================================================================

15.1 RECURSION PRINCIPLES
-------------------------
Every recursive function must contain:
1. Base Case: Halting condition preventing infinite recursion.
2. Recursive Step: Reduces problem size towards base case.

15.2 BACKTRACKING TEMPLATE
--------------------------
Algorithm search strategy exploring search tree depth-first, pruning invalid branches.

General Form:
  void backtrack(State state, ChoiceList choices) {
      if (isSolution(state)) {
          processSolution(state);
          return;
      }
      for (Choice choice : choices) {
          if (isValid(choice, state)) {
              makeChoice(state, choice);
              backtrack(state, remainingChoices);
              undoChoice(state, choice); // Backtrack step
          }
      }
  }

Classic Problems: N-Queens, Sudoku Solver, Subset Sum, Permutations.


================================================================================
SECTION 16: DYNAMIC PROGRAMMING (DP) CONCEPTUAL FRAMEWORK
================================================================================

Dynamic Programming solves optimization problems by combining solutions to subproblems 
when subproblems overlap.

Two Key Properties:
1. Optimal Substructure: Optimal solution to problem contains optimal solutions to subproblems.
2. Overlapping Subproblems: Problem can be broken down into subproblems reused multiple times.

Approaches:
1. Top-Down with Memoization: Recursion augmented with lookup table.
2. Bottom-Up with Tabulation: Iterative state building from smallest subproblems.


================================================================================
SECTION 17: CLASSIC DYNAMIC PROGRAMMING PROBLEMS
================================================================================

17.1 0/1 KNAPSACK PROBLEM
-------------------------
Given weights w[] and values v[] of N items, fill knapsack of capacity W for max value.
- DP State: dp[i][w] = max value using first i items with weight limit w.
- Recurrence:
  dp[i][w] = dp[i-1][w]  (if w[i-1] > w)
  dp[i][w] = max(dp[i-1][w], v[i-1] + dp[i-1][w - w[i-1]])
- Time: O(N * W), Space: O(W) optimized.

17.2 LONGEST COMMON SUBSEQUENCE (LCS)
------------------------------------
- DP State: dp[i][j] = length of LCS of str1[0..i-1] and str2[0..j-1].
- Recurrence:
  If str1[i-1] == str2[j-1]: dp[i][j] = 1 + dp[i-1][j-1]
  Else: dp[i][j] = max(dp[i-1][j], dp[i][j-1])
- Time: O(N * M)

17.3 LONGEST INCREASING SUBSEQUENCE (LIS)
-----------------------------------------
- DP Approach: O(N^2)
- Patience Sorting + Binary Search Approach: O(N log N)

SECTION 18: GREEDY ALGORITHMS
================================================================================

Greedy algorithms make locally optimal choices at each step hoping to find a global optimum.
Requires Proof of Correctness:
- Greedy Choice Property: Globally optimal solution can be reached by making local choice.
- Optimal Substructure.

Examples: Fractional Knapsack, Huffman Coding, Dijkstra, Prim, Activity Selection.

SECTION 19: DIVIDE AND CONQUER
================================================================================

1. Divide problem into smaller subproblems.
2. Conquer subproblems recursively.
3. Combine subproblem solutions.

Examples: Merge Sort, Quick Sort, Strassen's Matrix Multiplication, Closest Pair of Points.

SECTION 21: SEARCHING AND PATTERN MATCHING
================================================================================

21.1 BINARY SEARCH
------------------
Iterative search on sorted arrays in O(log n) time.
Lower Bound / Upper Bound pattern implementations.

21.2 KNUTH-MORRIS-PRATT (KMP) ALGORITHM
----------------------------------------
Pattern matching in O(N + M) time using Longest Prefix Suffix (LPS) array (Pi table).
Avoids unnecessary comparisons by shifting pattern intelligently.

21.3 RABIN-KARP ALGORITHM
-------------------------
Uses rolling hash to match pattern in O(N + M) average time.

SECTION 22: BIT MANIPULATION
================================================================================

Basic Operators: AND (&), OR (|), XOR (^), NOT (~), Left Shift (<<), Right Shift (>>).

Tricks & Properties:
- Check if i-th bit is set: (x & (1 << i)) != 0
- Set i-th bit: x | (1 << i)
- Clear i-th bit: x & ~(1 << i)
- Toggle i-th bit: x ^ (1 << i)
- Turn off lowest set bit: x & (x - 1)
- Is Power of Two: x > 0 && (x & (x - 1)) == 0

SECTION 23: ADVANCED DATA STRUCTURES
================================================================================

23.1 TRIE (PREFIX TREE)
-----------------------
Tree structure for fast string retrieval by prefixes.
Each node contains array of pointers (size = alphabet size) and isEndOfWord flag.
- Search/Insert Time: O(length of string).

23.2 SEGMENT TREE
-----------------
Binary tree used for point updates and range query operations (sum, min, max) in O(log N).
Space Complexity: O(4N).

23.3 FENWICK TREE (BINARY INDEXED TREE - BIT)
---------------------------------------------
Array-based tree structure performing prefix sums and point updates in O(log N).
Uses LSB trick: x & (-x). Fits in O(N) space.


================================================================================
SECTION 24: SYSTEM DESIGN AND HARDWARE AWARENESS
================================================================================

24.1 CACHE LOCALITY
-------------------
Modern CPUs rely on L1/L2/L3 caches. 
- Contiguous memory access (Arrays) experiences high cache hit rates (Spatial Locality).
- Node-based structures (Linked Lists, Binary Trees) cause frequent cache misses 
  due to pointer chasing across random heap memory locations.

24.2 BIG-O VS REAL-WORLD PERFORMANCE
-------------------------------------
An algorithm with O(N log N) runtime with high constant factors may run slower 
than an O(N^2) algorithm for small input sizes N < 50.
Examples: Timsort / IntroSort use Insertion Sort for small partitions.

MODULE PAGE 1: DEEP DIVE DRILLS & IMPLEMENTATION ARCHITECTURES
--------------------------------------------------------------------------------

Detailed Study Focus 1:
Data structures and algorithms require precise implementation details and continuous
refinement of analytical skills. When dealing with complex systems, understanding
the underlying memory model and CPU dynamics is paramount.

1. Memory Overhead and Pointer Alignment:
   - Modern 64-bit architectures utilize 8-byte pointer sizes.
   - Dynamic memory allocators introduce metadata overhead per allocation chunk.
   - Fragmented heap memory leads to performance degradation due to page faults 
     and CPU cache misses.
   - High-performance systems utilize pool allocators or arena allocators to 
     mitigate allocation overhead for graph nodes and tree elements.

2. Comprehensive Complexity Breakdown:
   - Amortized Analysis Methods: Aggregate Method, Accounting Method, Potential Method.
   - Potential Method Equation: Phi(D_i) mapping data structure state D_i to real number.
   - Amortized cost c_i' = c_i + Phi(D_i) - Phi(D_{i-1}).

3. Algorithm Design Patterns:
   - Two Pointers: Fast and Slow Pointers, Opposite End Pointers.
   - Sliding Window: Fixed Size Window, Variable Size Window with Dynamic Shrinking.
   - Divide and Conquer: Decomposition, Independent Solution, Recombination.
   - Dynamic Programming: Identifying Subproblems, Defining State Variables, Establishing Transitions.
   - Branch and Bound: Systematic Search with Optimization Bounds for Combinatorial Problems.

4. Practical Coding Considerations:
